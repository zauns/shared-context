# 06 — UI

**Status:** implemented (M4); drawer is read-only, editing in M5, attachments/palette in M6
**Depends on:** [05-http-api](05-http-api.md), [03-concurrency](03-concurrency.md), [07-attachments](07-attachments.md)
**Feeds:** M4, M5, M6, M7

## Routes

| Route | View |
|---|---|
| `/` | Last Project board, or Project picker/setup |
| `/projects/:key/board` | Kanban board |
| `/projects/:key/issues/:issueKey` | Board with the Issue drawer open; deep-linkable |
| `/projects/:key/settings` | Project settings, Modules, docs allowlist, backups, trash |
| `Ctrl/Cmd+K` | Global command palette overlay; no route |

Unknown routes fall back to the board or the Project picker, not a blank page.

## App shell

- Left sidebar: Project list with open-Issue counts, add Project (UI), settings, theme toggle.
- Top bar: Project name, search input, filter button, `New Issue`, connection/SSE indicator.
- Main area: the board. The drawer overlays the right side without unmounting the board.
- On narrow screens (<1024px) the sidebar collapses; on <768px the drawer becomes full-width.

## Board

- Six columns in fixed order: `backlog`, `todo`, `in_progress`, `review`, `done`, `cancelled`.
- Done and Cancelled are collapsible with counts; collapse state is per Project in `localStorage` (`sc.board.collapsed.<projectKey>`). They start expanded on wide screens and collapsed on narrow screens.
- Column header: Stage name, filtered count, `+` create button pre-filling that Stage, collapse toggle.
- Cards are ordered by `position`, then id. A `Sort` toggle (priority / last updated) is view-only and disables dragging while active.
- Drag-and-drop uses dnd-kit. Dropping on a column calls `move`; dropping on a card computes a midpoint position. The move is optimistic; on `409` or network failure the card rolls back and a toast explains why.
- Filters can hide cards. Dragging a filtered card is allowed; if the move makes it stop matching, show an undo toast.
- Empty column: subtle "No Issues" with the create shortcut.
- Per-column cap 500 with a "Load more" affordance if the API reports `has_more`.

### Card anatomy

Only title and attributes; no description preview.

- Key (`SHC-42`) and title.
- Priority chip: urgent red, high orange, medium amber, low blue, none gray.
- Assignee name/avatar.
- Module tag.
- Blocked badge with a tooltip showing the reason.
- Attachment count and comment count.
- Child progress bar `done/active` when the Issue has children.
- Relative updated time.
- Blocked and priority are never conveyed by color alone; text labels remain.

## Issue drawer

Width ~720px; deep-linked by URL. The board stays visible behind it.

- Header: key, editable title, copy-link, close, overflow menu (delete, open full page later).
- Metadata grid: Stage select, Priority select, Assignee select, Module select, Parent picker, Blocked toggle + reason popover.
- Description: rendered Markdown; `Edit` opens a textarea with Write/Preview. `Save`/`Cancel`; the server receives `expected_rev`.
- Children: progress, list of child cards (key, title, Stage, Priority, Assignee), `Add child` prefilled with the parent.
- Attachments: list/grid with image thumbnails, filename, size, uploader, date; upload/dropzone; click opens with the OS; download; remove.
- Links: list with label/URL; add form; open in browser; remove.
- Comments: chronological flat list, Markdown body, author/time; composer at the bottom; edit/delete own; no threading.
- Activity: timeline grouped by day; actor, field changes, attachments/links/comments; load more.
- Delete: confirmation; if children exist, require an explicit cascade checkbox and show the count.
- Sections are collapsible; collapse state is local to the drawer session.

## Create Issue

- Modal opened by `New Issue`, `n`, or the column `+` (pre-fills Stage).
- Fields: title (required), description, Stage, Priority, Assignee, Module, Parent, links.
- Attachments are uploaded after creation from the drawer; the create modal stays fast and atomic.
- `Cmd/Ctrl+Enter` submits, `Esc` closes, focus starts in the title.
- Validation inline; server errors map to fields where possible.

## Filters and saved views

- Text search (FTS), Stage multi-select, Priority multi-select, Assignee, Module, parent/child relation, Blocked, has attachments, updated date.
- AND across filter types; OR within a multi-select.
- Filter state in the URL query string so views are shareable/bookmarkable.
- Column counts reflect the filtered set; `filtered_count` is shown in the toolbar.
- `Clear all` resets the URL state.
- Named saved views live in `localStorage` under `sc.savedViews.<projectKey>`; apply, rename, delete. No server-side views in v1.

## Command palette

- `Ctrl/Cmd+K`.
- Debounced cross-project Issue search (150ms), recent Projects, actions: new Issue, go to board, project settings, toggle theme.
- Results show Project key + Issue key + title + Stage.
- Arrow keys navigate; Enter opens; Esc closes.
- Empty query shows recent Issues and Projects, not an empty box.

## Editing and conflict UX

- Immediate save: Stage, Priority, Assignee, Module, Blocked. The control is optimistic and reverts with a toast on error.
- Explicit save: title and description. A dirty editor is never clobbered by SSE.
- Every core-field write carries the current `rev`.
- On `409`:
  - Inline fields: revert to the server value, toast "Updated by X; your change was not applied", refetch.
  - Title/description: keep the draft, show a banner "Updated by X at HH:MM" with `Reload latest` (discards draft after confirmation) and `Copy draft`. No `Overwrite` button.
  - Drag-and-drop: rollback and toast.
- SSE events update clean views; if the drawer is dirty, show the banner and let the human decide.
- While dragging a card, defer SSE updates for that card until the drop settles.

## Settings

### Project settings

- Name, immutable key, description.
- Root path picker (text input; validates existence).
- Doc allowlist editor (globs, one per line, defaults shown).
- Modules manager: add, rename, color, delete if unused; shows usage counts.
- Trash: deleted Issues grouped by `deletion_batch`, with deleted-by/at and `Restore batch`.
- Backup status and `Backup now`.
- Export Markdown zip / JSON.
- Delete Project (only when empty).

### Global settings

- Theme and density.
- MCP token: masked, copy button, regenerate with confirmation.
- Data paths, version, uptime, last backup.
- Startup instructions (Task Scheduler) and the Reasonix `[[plugins]]` snippet.
- Actor list: display name, `can_read_images`, color. The owner can edit capabilities; agent rows are auto-created.

## State and data fetching

- TanStack Query for server state. Query keys: `['board', projectKey, filters]`, `['issue', issueKey]`, `['projects']`, `['actors']`, `['modules', projectKey]`.
- SSE invalidates/patch-updates the board and the open Issue. Reconnect uses `Last-Event-ID`; a `resync` event triggers a refetch.
- URL state via React Router search params.
- Local UI state: theme, density, collapsed columns, saved views, last Project, drawer section collapse.
- No Redux. Mutations are small hooks around the API client; optimistic updates only for drag/order and immediate metadata fields.

## Theme, density, accessibility

- Dark theme by default; light toggle; CSS variables + Tailwind.
- Compact density by default; comfortable option.
- Focus rings visible; all controls keyboard-operable; dnd-kit keyboard sensor.
- Radix primitives for dialogs, popovers, selects, tooltips.
- Labels and text accompany color-coded priority/blocked states.
- Markdown sanitized; links open with `rel="noopener noreferrer"`.
- Loading skeletons, empty states, and retry actions for every data surface.

## Acceptance criteria

- The board shows six columns and a blocked badge without a Blocked column.
- A card shows child progress without expanding.
- Dragging a card persists `position` and rolls back on conflict.
- Opening `/projects/SHC/issues/SHC-42` opens the board with the drawer.
- Filters round-trip through the URL; saved views survive reload.
- A simulated 409 in the description editor preserves the draft and offers reload/copy.
- Uploading an image shows a thumbnail; clicking it opens the OS handler.
- The command palette finds an Issue in another Project.
- The UI is usable at 1280px and degrades to a scrollable board at 768px.
